# tetsudo_app 設計ドキュメント

乗り鉄（乗りつぶし）向けアプリの設計メモ。まずは作者本人が使い、将来的な一般公開も見据える。
PC・Android・iOS で使えること。

> このドキュメントは設計フェーズ（フェーズ0）の合意事項をまとめたもの。実装はまだ無い。

---

## 1. コンセプト

手書きの行程表（旅のしおり）をデジタル化しつつ、**「乗った路線を塗りつぶす」体験**を中核に据えた乗り鉄アプリ。

### 中核となる価値（最重要）
**「塗りつぶす＝乗りつぶす」という手動の行為そのものが報酬**。ここの手触り感を最優先で作り込む。

- 地図上の駅間をタップ／なぞると、じわっと色が乗るアニメーション＋触覚フィードバック（バイブ）
- 塗った瞬間に達成カウンタ（乗りつぶし率 %・距離 km・駅数）がリアルタイムに動く
- 判定（乗ったか／通過・下車・泊まった）は **すべて手動**。自動判定はしない（楽しみを奪わないため）

## 2. 確定した方針（フェーズ0の合意）

| 項目 | 決定 |
|---|---|
| 技術スタック | **Flutter**（1コードで iOS / Android / Web / デスクトップ） |
| データ調達 | **手入力中心**。時刻表連携は後回し。路線・駅マスタのみ外部データを取り込む |
| MVP の軸 | **計画と記録の両方の最小セット**を薄く実装 |
| 費用管理 | **後回し**（モデル上に居場所だけ確保、MVP には入れない） |
| 状態判定 | **すべて手動**（自動判定なし） |

---

## 3. 設計の基本原則

1. **実績は計画から独立して存在する**
   - 計画になく、ただ乗った路線も記録できる
   - 過去の乗りつぶしを、計画も日付も無しに一括で反映できる
2. **塗りつぶし／駅ステータスは「実績」だけから導出する**（計画には一切依存しない）
3. **更新しても前の情報を残す**（追記型・履歴保持）
4. **状態はすべて手動**で切り替える

---

## 4. データモデル

3つの層で構成する。

### 層1：マスタ（全国共通の参照データ・取り込むだけ）

| エンティティ | 主な属性 | 役割 |
|---|---|---|
| **Line（路線）** | 事業者・路線名・色 | 一覧 / 分類 |
| **Station（駅）** | 駅名・緯度経度・所属路線 | 駅ステータスの対象 |
| **Segment（駅間）** | 隣接駅 A–B・区間ジオメトリ・距離 | **塗りつぶしの最小単位**（途中まで乗車に対応） |

> 「手入力中心」でも、この路線・駅・駅間ジオメトリだけは外部データが必須。
> 第一候補：**国土数値情報（鉄道データ N02）** ＋ 駅順序の補完に **駅データ.jp**。
> フェーズ0で唯一“調達が要る”もの。

### 層2：実績（生涯の真実の台帳・塗りつぶしの源）

| エンティティ | 主な属性 | ポイント |
|---|---|---|
| **RideRecord（乗車実績）** | 乗った駅間（複数可）・日付（任意/曖昧可）・列車（任意）・ソース（手動 / 計画から / 一括取込）・Leg への紐付け（任意, null 可） | **Trip 無しで単独成立**。一括取込もこれ |
| **StationVisit（駅訪問）** | 駅・日付・状態（通過 / 下車 / 泊まった） | 駅ステータスの源 |

→ **塗りつぶしマップ = RideRecord の集計**、**駅ステータス = StationVisit の集計**。
どちらも派生ビューで、計画には依存しない。

### 層3：計画／旅程（手書き行程表のデジタル版）

| エンティティ | 主な属性 |
|---|---|
| **Trip（旅程）** | タイトル・期間 |
| **Day（日）** | 日付・曜日 |
| **Leg（行程＝区間）** | 発駅 / 発時刻・着駅 / 着時刻・列車名 / 種別・路線・号車 / 座席・乗車時間・待ち時間 |
| **Item（しおり項目）** | 種別（食事 / 宿泊 / 寄り道 / 観光）・名称・場所・時刻・メモ |
| **Photo（写真）** | 各 Leg・各 Item にぶら下げ |
| **Cost（費用・後回し）** | 交通費 / 宿泊費・人数・割り勘（設計だけ確保） |

### 計画↔実績の関係

```
Leg(計画)  ──0..1──  RideRecord(実績)
```

| ケース | 表現 |
|---|---|
| 計画通り乗った | Leg と RideRecord が紐付く |
| 計画したが乗らなかった | Leg だけ（実績なし） |
| 計画になく乗った | RideRecord だけ（Leg なし） |
| 過去の一括取込 | RideRecord だけ（Trip すら無い） |

### ER 図

```mermaid
erDiagram
    Line ||--o{ Segment : has
    Line ||--o{ Station : belongs
    Segment }o--|| Station : from
    Segment }o--|| Station : to

    Trip ||--o{ Day : has
    Day ||--o{ Leg : has
    Day ||--o{ Item : has
    Leg ||--o{ Photo : has
    Item ||--o{ Photo : has

    Leg |o--o| RideRecord : "0..1 紐付け"
    RideRecord }o--o{ Segment : covers
    StationVisit }o--|| Station : at
    RideRecord ||--o{ StationVisit : "生成しうる(任意)"
```

### 履歴保持（前の情報を残す更新）

RideRecord / StationVisit / Leg は **追記型**。編集すると旧版を履歴として保持する。
例：「2024年は通過 → 2026年は下車」の変遷がそのまま残る。

実装方針（MVP）：各レコードに `version` と `updatedAt` を持たせ、変更時に旧レコードを history テーブルへ退避（イベントログ的）。

## 5. 画面構成（MVP）

1. **マップ（ホーム）** … 全国路線図。塗りつぶし表示＋達成カウンタ。塗る操作の中核
2. **乗車記録**（RideRecord 作成 / 編集） … 単発の「乗った」を手動登録
3. **一括取込** … 過去の乗りつぶしをまとめて反映（後述）
4. **駅詳細** … 駅の状態（通過 / 下車 / 泊まった）を手動切り替え
5. **旅程一覧 / 旅程詳細** … 手書き行程表のデジタル版（計画・実績）
6. **行程編集（Leg / Item）** … 発着時刻・列車・座席・しおり項目・写真
7. **実績サマリ** … 乗りつぶし率・距離・駅数・履歴

### 塗りつぶしUX（中核体験）の要件
- タップ／なぞりで Segment を塗る → 色がじわっと乗るアニメ＋触覚フィードバック
- 塗った瞬間に達成カウンタが動く（%・km・駅数）
- 駅はタップで 通過 → 下車 → 泊まった をトグル、状態ごとに見た目が変化
- オフラインでも塗れる（手入力中心なのでネット不要）

### 一括取込フロー
- 路線を選ぶ → 路線全体／区間をまとめて「乗車済」に
- 日付は任意（不明・おおよそ可）
- ソース＝「一括取込」として記録（後から個別編集できる）
